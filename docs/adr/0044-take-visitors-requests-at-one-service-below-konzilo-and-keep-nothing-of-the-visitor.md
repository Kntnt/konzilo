# ADR 0044: Take visitors' requests at one service below `/_konzilo/`, and keep nothing of the visitor

**Date:** 2026-11-03, amended 2026-11-11 · **Status:** Accepted as a technical choice, within Thomas's decision of a small Node service per site (ADR 0001); Thomas may veto. Settled on 2026-11-11 with the first kind, the forms', as technical choices Thomas may veto: `visitors` in a network with no way out that only the web server shares; the service's data as one database in the volume `service-data`, its changes counted in steps; the address and the host passed in headers of the web server's own; and the digest as an HMAC under a key of the service's, in the clock's own windows, counted in memory alone. Settled on 2026-11-11, when Admins and Editors first read the submissions, as a technical choice Thomas may veto: `editors` opens the same database, in the same volume, and answers for it on the admin host, so that `visitors` stays in its network with no way out and the admin host keeps one service behind it. Settled on 2026-11-11 too, as a technical choice Thomas may veto: both roles mount the site's folder read-only, as the builder and the preview do, rather than its site description alone, since a mount of one file holds on to the file it was made with and never shows one replaced, as Git and an editor write one; the service tells a replaced description by its inode as well as its size and moment. Each role then sees the rest of the site repository too, read-only, so a server keeps its secrets outside it, where `KONZILO_SECRETS` names them.

## Decision

- **Reserved paths.** Visitors' browsers reach a site's services at paths below `/_konzilo/`, on the site's own host and on its pre-launch address, behind its password there. Each service takes one path: `/_konzilo/search` goes to Typesense, and the rest to the service. No release page may be there; the checker and the build refuse one. The core's own files below the prefix are the exceptions: the page a form's post gets while the service does not answer (ADR 0045), and the consent scripts with their stylesheet below `/_konzilo/consent/`, which the web server serves as files, `GET` alone, before it passes the prefix to the service (ADR 0049).
- **One program in two roles,** the `visitors` and `editors` containers (ADR 0005), under limits, with SQLite (`node:sqlite`) in a volume of the customer's own. Only `editors` reaches the source repository. It has no database server. `visitors` is in a network of its own that only the web server shares, with no way out, until mail needs one. The service's data is one database, `service.sqlite`, in the volume `service-data`: the service's key, made at its first start, and each kind's storage. Both roles open it: `visitors` keeps what visitors send, and `editors` reads it for Admins and Editors, such as a form's submissions. Each change to what it holds is a step taken once, counted in the database's own `user_version`, so a later duty adds a step and an older database is brought up to it at the next start.
- **It accepts only kinds the core registers.** Each kind has a path, methods, content types, a size limit, a check and storage. A kind takes the requests to its path and every path below it. It may answer with JSON, `429` with `Retry-After`, or `303` back to a path on the site. The service refuses a method a kind does not take, a body over its limit and a body of a type it does not take, and answers `no-store` and `nosniff`. It never sets a cookie.
- **Limits:** each request within ten seconds and 64 MB; the web server cuts a body off at a megabyte, or a kind's own higher limit; over-limit bodies are refused by length, unread.
- **The web server passes on** the request's method, path, query, body with its type and length, the visitor's address, and `Origin`, `Referer` and `Sec-Fetch-Site`, and nothing else: no cookie, browser, password or language. It keeps no log of these requests. The address, and the host the request came to, go in headers of its own, `X-Konzilo-Client` and `X-Konzilo-Host`, which it sets whatever the visitor sent, as the dev server does locally. Every path below the prefix goes to `visitors` but `/_konzilo/search` and the consent scripts' files, `GET` and `HEAD`.
- **The service keeps them from every kind.** A kind gets only what it makes of them: whether the request came from a page of the site's own (`Sec-Fetch-Site: same-origin`, or, from a browser that sends none, an `Origin` or else a `Referer` on the host the request came to or one of the site's public hosts); and a keyed digest of the address and a window of ten minutes, with the window's end. The key comes from a secret in the service's data. **No IP address, user agent or referrer is kept,** and no log of the requests is written. The digest is HMAC-SHA256 of the address and the window's number, under a key derived from the service's key; a window is one of the clock's own ten minutes, `:00` to `:10` and on, and what a kind counts by the digest it holds in memory alone, forgotten as the window ends.
- **For editors,** on the admin host, each call checked against Forgejo: the check before saving, the list of titles, status, the preview gate, share links and the pages in Sveltia, the forms' submissions below `/_konzilo/submissions` among them (ADR 0045). Whoever may not write is told nothing there, not even which forms there are.
- **Timed duties:** mail for each pending submission, retention, spam after seven days, consent records after 13 months, violations after 30 days, expired share links, and unused previews.
- **What a build hands over.** At the switch, before visitors can send anything from a new release, the build hands the service that release's consent revisions. The service reads the forms from the site description of the code in use, again whenever its file changes, from the site's folder, mounted whole. A local copy works the same way.
- **Kept out of Git:** recipients lists, retention and the service's secret, in SQLite, edited on a page.
- **Its data joins** the archive, backups, restores and the drill (ADR 0006). A service down leaves the public pages answering; a form says it was not sent (ADR 0045).

## Why

- The page's own origin needs no CORS, and a Content Security Policy needs only `'self'`, and it works the same before and after launch and locally.
- A digest that changes every ten minutes counts one client and is gone with its window. It cannot be followed across windows, and no address is kept.
- Handing a kind the verdict alone keeps the address out of every kind's code, by construction.
- A store of its own lets backups, restores and archives carry what visitors send, and consent can be demonstrated.

## Considered and rejected

- **A services host per server.** It is cross-origin, so it needs CORS, policy entries and a certificate of its own.
- **The admin host.** It puts visitors on the login domain.
- **A beacon logged by the web server.** It loses request bodies.
- **No server-side records.** Consent could not be demonstrated.
- **A digest made by the web server,** or its rate limits. Caddy's standard build has no keyed hash among its placeholders and no keyed window.
- **A CSRF token.** No cookie or session authorizes anything here, so the origin is what matters.
