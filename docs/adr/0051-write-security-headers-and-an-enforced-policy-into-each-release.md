# ADR 0051: Write security headers and an enforced policy into each release

**Date:** 2026-10-29, amended 2026-11-10 and 2026-11-25 · **Status:** Accepted. Settled by Thomas on 2026-10-29: the Content Security Policy is generated at every build, enforced from the first day, an Admin adds the sources tags need, and violations go to a log. Settled by Thomas on 2026-11-10: `data:` images allowed by default, which a site may switch off. Settled by Thomas in triage on 2026-11-25: the *Policy violations* page comes with the counts. The rest is a technical choice; Thomas may veto, among them, chosen on 2026-11-25 when the reports were first counted: a report a browser extension caused, by what it blocked or by the file that asked for it, is not counted at all, rather than kept by its scheme alone; a longer path is cut to its first 300 characters, rather than refused; a report is counted only for a directive a policy can have, in lower case, and only where the page it names is on the host the request came to or one of the site's public hosts, beside the request's own check; of what was blocked, an `http`, `https`, `ws` or `wss` address keeps its origin, any other its scheme alone, written with its colon as a policy writes it, `data:`, and `wasm-eval` counts as `eval`, while `self`, a keyword of Trusted Types and anything else that names nothing is not counted; a body taken is answered `204`, a body that is no report `400`, more than 100 reports `413`, reports not from the site's own pages `403`, and a client that has had its 100 counted in the window `429` with `Retry-After` until the window ends, while a body that takes it past them has its first counted up to the 100 and the rest dropped; the moment an entry was last seen is when the service took the report, whatever the report says of its age; the entry for the rest is one row of the same table with its page, directive and blocked origin empty, which the page shows last, at the foot of its table, and which goes 30 days after it was last seen as any other; the counts are a table of their own, `violation`, added by a schema step of its own, and kept by a module of their own, `src/service/violations.js`, which asks the store's connection itself; the `editors` role forgets the old ones at its start and each minute, beside the forms' retention; and the page, in Swedish *Policyöverträdelser*, is on every site, since every release has a policy, reads the counts at `/_konzilo/violations` on the admin host, as the instance administrator may too, and shows code with no address in words, *Code written into the page* and *Code made from text (eval)*.

## Decision

- **The build writes the headers into the release as `_headers`,** `/*`, then one indented `Name: value` per header; then, on a release with consent scripts, `/_konzilo/consent/*` with `Cache-Control: public, max-age=300` alone, which the web server takes for that folder and refuses for any other path or header (ADR 0049). One set holds for every answer: HSTS for one year, with `includeSubDomains` only by opt-in and never `preload`; `nosniff`; `strict-origin-when-cross-origin`; framing by the site alone, or by the origins it lists; a permissions policy that turns off camera, microphone, geolocation, payment, USB, serial, HID and Bluetooth, and gives each feature an embed's player is given to the site and the players' origins; COOP `same-origin`.
- **`security` in the site description** holds the site's choices: the opt-ins `includeSubDomains` and `frameAncestors`, and `dataImages`, true unless the site says `false`, and refused as anything but `true` or `false`.
- **One policy per release,** enforced, also by share links. `'self'` first in every directive that loads: `default-src 'self'`; the SHA-256 of each inline script in `script-src`, of each inline style element in `style-src`, and of each distinct `style` attribute value in `style-src-attr` under `'unsafe-hashes'`, collected over every page as built, a `<template>`'s and a `<noscript>`'s content too; in `frame-src`, the player origins of the embed services the release's panels show; the registry's hosts per kind of request; `data:` in `img-src`, unless `security.dataImages` is `false`; `object-src 'none'`, `base-uri 'none'`, `form-action 'self'`, `frame-ancestors`; last, reporting to `/_konzilo/violations`, as `report-uri` and `report-to`. Preview and share policies report nothing, so that editors' previews are not logged.
- **Never offered:** `'unsafe-inline'`, `'unsafe-eval'`, `*` alone, a scheme alone but `data:` in `img-src`, `data:` or `blob:` for scripts, or a nonce.
- **The build fails** on an inline event handler or a `javascript:` address, naming the page and the element, and on a header longer than a host takes, 65,536 characters.
- **The host takes the file before the release is current,** so that the policy goes live with its pages: only names on its list, each once, printable ASCII, nothing the web server reads as its own. A file with anything else is refused whole, and the site keeps its release. The web server's own answers carry the headers too.
- **The dev server sends the same headers but the policy,** of which it sends the framing part alone, since its own code is inline.
- **Reports** are kept by the service, in its role for visitors at `/_konzilo/violations` (ADR 0044), as counts of page path, directive and blocked origin, with when each was last seen, and no IP address, user agent or referrer, for 30 days after an entry was last seen, which the role for editors forgets at its start and each minute, overwritten where it stood. It takes `application/csp-report` and `application/reports+json`, at most 100 reports in a body of at most 128 KiB. Of each it keeps the path without its query, at most 300 characters, the effective directive, and what was blocked: the origin, the scheme alone, or `inline` or `eval`. A report a browser extension caused is not counted. It refuses reports not from the site's own pages, and counts at most 100 of one client in ten minutes. Past 1,000 entries a new combination counts into one entry for the rest. An Admin reads them on *Policy violations*, the most recently seen first, with the entry for the rest last; an Editor is told only that the page is an Admin's.
- **The admin host** has a policy of its own for Sveltia, and basic headers, and hosts no editor-written HTML.

## Why

- Astro's `<meta>` policy cannot control framing or send reports.
- Hashing attribute values keeps the content files unchanged.
- Every report holds the whole policy, so a limit of a few kilobytes would refuse every report of a site with many hashes.
- A design embeds its icons in its stylesheet as `data:` images, which `'self'` alone blocks, so the page does not look as designed. An image runs no code, even an SVG one, so `data:` in `img-src` loosens nothing that runs code or styles a page; inline styles and `data:` scripts stay blocked. A site with strict requirements switches it off.

## Considered and rejected

- **Headers in the web server's site file.** Only a release's build knows the hashes of its code.
- **Astro's meta policy alone.**
- **`'unsafe-inline'` for tags.**
- **`data:` images by opt-in.** Every site whose design embeds an icon would have to know to ask, and its icons would be missing until it did.

## What practice has shown

- In Compose the web server has no admin endpoint, and no container may reach another's signals, so Caddy runs with `--watch`, and a release's rules lie beside its pages, imported by a glob, since a file named outright that is not there stops the server before the first build. It looks each second, so a new policy goes live up to a second or two after `current` has moved. It reloads only when the rules have changed, which a publish seldom does, and a reload closes idle connections.
- Caddy's `header` reaches a redirect, a 404 and a 410 alike.
- Each engine reports a violation its own way (2026-11-25, Chromium 156, Firefox 157 and WebKit's Safari 27.2 as Playwright drives them, on `localhost`). Firefox sends to the group `report-to` names, by the Reporting API, `application/reports+json`, at once, with `Sec-Fetch-Site: same-origin`. WebKit sends to `report-uri`, at once, as `application/csp-report`, but one report in the Reporting API's shape rather than under `csp-report`, with `Origin: null` beside `Sec-Fetch-Site: same-origin`, and the default port in the address blocked; the service takes both shapes under that type. Chromium sends to `report-uri` with `Origin` and `Sec-Fetch-Site: same-origin` where the policy has no `report-to`; given `report-to`, it reports by the Reporting API alone, and there it queued the report for the group but never found the endpoint `Reporting-Endpoints` names, in a profile of its own too, so it sent none. The acceptance suite therefore sends the report Chromium queued, read through its DevTools, as Chromium's uploader sends one.
