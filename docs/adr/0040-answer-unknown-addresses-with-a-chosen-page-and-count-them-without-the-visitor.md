# ADR 0040: Answer unknown addresses with a chosen page, and count them without the visitor

**Date:** 2026-11-02, amended 2026-11-13, 2026-11-25 and 2026-11-26 · **Status:** Accepted. Settled by Thomas on 2026-10-29: the page is chosen in the site settings and written in the editor, with no address of its own; `404` and `410` answer with it; the log holds the address, a count and the last time asked, and no IP address, user agent or referrer; entries expire within 30 days; an Admin makes a rule from the log with a button. On 2026-11-02 he confirmed that it is written in Crepe. The rest is a technical choice; Thomas may veto, among it that a post chosen for addresses not found and as the start page is this page alone (2026-11-13), and these, made as the log and its page were built (2026-11-25): the web server writes the log in a volume of its own, `not-found-log`, which the service in its role for editors reads and folds into counts in a volume of their own, `not-found`, reading the release in `site-public`, read-only, so that no container gains a way out; a fold runs every five minutes and also as an Admin opens the page or hides an address, so that the page shows what was asked for until then; the log rolls over at 10 MiB to one older file, so that what a flood writes between two folds beyond that is not counted; an address is the path as the browser sent it, percent signs and all, as the dev server counts it; a file of the release holds an address where the file is at its path or the folder there has an `index.html` or an `index.rss`, and the fold also lets go an address a rule of the release answers with anything but `404`, as the dev server does, while one a rule answers with `404` goes on being counted and stays off the page; *Redirect…* makes a `301` to a target the Admin types, a path on the site or an `https://` address, with no form lock, since no form edits `redirects.json`; the buttons that make a rule are offered only at an address a rule may have as its source, and *Hide* everywhere; a hidden address cannot be shown again on the page, and comes back only once it has gone from the counts; and the counts' volumes are a kind of their own in the Compose guide, *transient*.

## Decision

- **The setting,** in the group `notFound`, holds one published post of a type with an address, by ID.
- **The chosen post.** The intake writes its title and body as `content/not-found.md`, the one entry of the collection `notFound`, and leaves it out of its type's collection. So it has no address: its own, old and other addresses answer as unknown; a link to it is written as its text, with a warning; a menu entry for it is left out, with a warning; and it is in no list, feed, sitemap, Markdown alternate or search.
- **One post for both.** A post chosen as the start page too ([ADR 0033](0033-keep-menus-settings-and-the-sites-identity-in-files-an-admin-edits.md)) is this page alone, since it has no address, and the settings page warns that the site shows its own start page.
- **Without a page that can serve,** the template's plain text in the site's language serves, and the build warns. Unlike a refused post, a refused page for addresses not found keeps no version published before.
- **Answered everywhere.** Astro builds the page as `404.html`, and the web server answers every address the order of addresses leaves to `404` with it and `404`, and a rule's `404` or `410` with it and its status, but below `/_konzilo/`. On a site in several languages each language has its own (ADR 0042).
- **The log.** The web server logs the public hosts' `404` answers with the path, without its query, and the time alone: its filter deletes the request and the answer before the line is written. Every five minutes these are folded into counts, in a file outside the repositories. Only `GET` and `HEAD`, paths of at most 300 characters, nothing below `/_konzilo/`, and at most 5,000 addresses, the least recently asked going first. An entry goes 30 days after it was last asked for, and at the fold after a file of the release holds it. The counts are in no backup or archive; a restore begins without them, and a purge takes the post's addresses out ([ADR 0078](0078-purge-a-deleted-entry-from-both-repositories-histories-and-carry-over-each-rewritten-saves-identity.md)).
- **Where it runs.** In Compose the web server writes the log, `{"ts":<seconds>,"path":"<path>"}` a line, to `/srv/not-found/not-found.log` in the volume `not-found-log`, and logs nothing of any other answer or host. The service in its role for editors reads that volume and folds it (`src/service/not-found.js`) into its counts in the volume `not-found`, in the form Astro's dev server keeps its own in (`src/not-found-counts.js`), each line once, by where the last fold stopped, in the file it stopped in, which a roll keeps by its inode. It reads the release in `site-public`, read-only, whose redirects each release keeps beside its pages as `_redirects`. A purge calls `notFoundLog().forget()`, or `forgetAddresses()` on the counts' file, with the post's addresses.
- **The page,** *Addresses not found*, for Admins, has *Redirect…*, *Answer 410* and *Hide*. An address a rule holds leaves the page at once. The service lists the addresses at `/_konzilo/not-found` on the admin host, most asked first, but those hidden and those a rule holds, of the release or of the source's `redirects.json` as it stands, which it reads by its own credential, and hides one at `/_konzilo/not-found/hidden`. *Redirect…* and *Answer 410* add the rule to the source's `redirects.json` from the browser, as an Admin's save of the redirect rules ([ADR 0036](0036-keep-every-redirect-as-a-rule-and-make-old-addresses-from-what-was-live.md)): one commit through Forgejo's API with what Sveltia signed in with, so that the build sees the Admin's push, after the checks the intake runs, so that a rule it would refuse, which would hold up every rule of the file, is never saved, and the Admin is told why.

## Why

- An editor writes the page, and the site's design shows it.
- Leaving the page out of its collection keeps it out of everything at once, with no filter to forget.
- Filtering in the web server means no IP address is ever written, not even for a moment.
- The service already shows the Admin's pages and asks Forgejo who is asking, so the fold beside it needs no program, port or way out of its own, and the page reads counts that one program alone writes.
- Reading the source's rules at each listing takes an address off the page the moment a rule for it is saved, whoever saved it and however, before any build.

## Considered and rejected

- **The page kept in its collection with a flag.** Every design would have to filter it out.
- **A full access log, filtered afterwards.** IP addresses would be written first.
- **Counting through the service.** Every `404` would run a program, and scanners would flood it.
- **The web server's log sent to the service over a socket.** The service would take every line as it came, scanners' floods too, and a stopped service would lose them; a file waits.
- **The release's rules read from `web-rules.caddy`.** It is written for Caddy, a source as Caddy matches it; the build's `_redirects`, kept beside the pages, says the same in the form every other reader of rules takes.

## What practice has shown

In Compose, with Caddy 2.11:

- `log_skip` sets a variable, `log_skip`, that the access log reads once the answer is written, so the host's routes skip every answer, and `handle_errors` sets it again: `true`, then `false` for a counted `404`, by a matcher of the error's status, the method, the path and the address. An error before any route, such as Caddy's own `400` for an empty host, has no variable set but by `handle_errors`.
- A `route` sorts after a `handle`, so `vars` and `log_append` stand bare in `handle_errors`, before its handles.
- `{http.request.orig_uri.path}` is decoded, so the line takes `{http.request.orig_uri}`, the address as the browser sent it, by `log_append`, and the filter's `regexp` cuts off its query before the line is written. The `json` encoder's `message_key`, `level_key` and `name_key` set empty leave out the line's message, level and logger, and `delete` takes `request`, `resp_headers`, `bytes_read`, `user_id`, `duration`, `size` and `status`, which leaves the time and the path.
- A segment longer than a file name may be is answered `400` by the file server, and so never counted.
