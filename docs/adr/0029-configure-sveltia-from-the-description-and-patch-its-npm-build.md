# ADR 0029: Configure Sveltia from the description, and patch its npm build

**Date:** 2026-11-03 · **Status:** Accepted as a technical choice, within Thomas's decision of Sveltia (ADR 0001); Thomas may veto.

## Decision

- **Configuration is generated, never committed.** `konzilo-cms` makes it from `site-description.json` and the settings groups at deploy and on a local start, with labels in the site's language. Nothing is stored that could drift.
- **Fields map plainly.** Text, number, toggle, date and select controls take Sveltia's own fields. A taxonomy or a parent is a relation by ID. A featured image is an object of image and alt text. Search and sharing is one object. Settings groups and menus are file collections with nested lists. Empty optional fields are left out, since the schemas refuse an empty string.
- **The build.** Sveltia's npm build (`npm/index.js`, not `dist/`, which holds unpkg addresses) at an exact pin, inside the core's package. It carries a data-file patch for each fault found, each failing loudly if its anchor moves.
- **The patches needed:** Forgejo's OAuth scopes, which 0.256.1 joins with commas; a retry when two people save at once; the wording above a `preSave` refusal, which the field gives by a global the patched dialog asks; and the "now available on mobile" banner. The same file patches what the field brings: a list item's selection (ADR 0030), a table cell's click (ADR 0021) and the runtime's probe of `new Function` (ADR 0016).
- **Backend.** The `forgejo` backend with PKCE only (`auth_methods`), no token sign-in, and the Simple Workflow.
- **Sveltia lives on the admin host,** `<site>.konzilo.app`, as static files, with a Content Security Policy of its own and without a cross-origin opener policy, since its sign-in uses a popup. That host never shows editor-written HTML.
- **`preSave` refuses.** A handler sends the draft to the service's check, and throwing stops the save with the reason. An address another post holds, a required field left empty, or a change only an Admin may make is stopped at that moment, naming where it is. The intake remains the check that counts.
- **Pages in Sveltia,** through `CMS.registerCustomPage`: Publishing, Submissions, Consent records, Policy violations, Addresses not found, Redirects with CSV, Recipients lists, Privacy texts and Users. Everything else an Admin edits is plain forms. A custom page gets no props, so it reads the user's token from Sveltia's storage (`sveltia-cms.user`), which is undocumented, and is pinned and tested at each raise.

## Why

- A description that drives every reader cannot disagree with itself.
- A file left to be regenerated by hand would drift, so nothing is left.

## Considered and rejected

- **Sveltia's Editorial Workflow.** It is a review step, which Thomas has settled against (ADR 0008).
- **A committed configuration file per site.** It would be a second definition.

## What practice has shown

Sveltia 0.256.1:

- The comma-joined scopes reach notifications and organisations (200), the patched ones do not (403). This holds on Forgejo 17.
- A refusal from `preSave` shows "There was an error while saving the entry. Please try again later." above Konzilo's reason, which is wrong for a refusal. The patched dialog takes the field's words where the reason is the field's, and any other failure keeps Sveltia's. The title stays "Error". Sveltia also logs the refusal with `console.error`.
- `preSave` runs after the entry is built from the draft, too late for a field to write what it holds back, so the body field writes within 50 ms of a key, on blur, and on Mod-S before Sveltia reads the draft.
- `registerFieldType` starts loading React, ReactDOM and Immutable at once, not when an entry opens, 285 KB (86 KB compressed) in chunks of their own, so they come after the first paint on every load.
- **Two people saving different entries at once:** in 2 of 6 rounds one got the error dialog, with "PushRejected Error: … cannot lock ref 'refs/heads/main'" as the reason. Through REST, 3 of 4 parallel saves got 403. Saving again worked, and the draft stayed in the form. A commit takes about 0.5 s, so it is rare on a small site.
- **Two people, one entry:** Sveltia warns the second person while editing and at Save, with *Save Anyway* or *Cancel*. *Save Anyway* overwrites the other person's change, which then stays only in Git's history; the warning comes also when they changed different fields. A stale `sha` alone gets 409 from Forgejo, so an old copy cannot overwrite by accident.
- Sveltia follows the browser's language, so it read "Logga in med Forgejo" and "Post sparad.", while collection and field names come from the configuration.
- A custom field's props are `value`, `field`, `forID`, `classNameWrapper`, `entry`, `getAsset`, `onChange`, `addFile` and `pickFile`. It cannot list other entries; a preview template gets `getCollection`. React is `window.__SVELTIA_CMS_REACT__`. Set `window.CMS_MANUAL_INIT = true` before loading the build, then `CMS.init({ config })` with `load_config_file: false`.
