State at 2026-11-10. Overwrite when it changes; this is not a history.

- **Repository:** private, `Kntnt/konzilo`, until Thomas names the public day. The code is under `AGPL-3.0-or-later`, with what a site adds left outside it by `SITE-EXCEPTION.md`, and the name is under `TRADEMARKS.md` (Thomas, 2026-11-10, ADR 0057 and 0058). The rights are Kntnt Sweden AB's, and work by others goes into the core only under `CONTRIBUTOR-AGREEMENT.md`, by its author's line in `CONTRIBUTORS.md` (ADR 0059). Not settled, and his to settle before that day: the registration of the name, which is not registered.
- **CI:** GitHub Actions stays off until the first usable version, when it goes on (Thomas, 2026-11-03). Until then `npm run gate` is the gate, as strict as CI would be: merge to `main` only after it passes on that commit. Do not settle for `npm test` in this checkout, which runs on this machine's Node rather than the pinned one.
- **Exists:** the npm package `@kntnt/konzilo`, one package at the repository's root: the content format (`content-format.md`, `src/format/`), the site description's checker (`src/site-description.js`), the settings groups, the post lists, the search index, the Astro integration (`src/astro/`), which builds a site from content files alone, the intake (`src/intake/`, `src/format/body.js`, `bin/konzilo-intake.js`), which writes them from source files, and the Crepe field for text elements (`src/cms/body/`). `bin/new-site` makes a site repository from `site-template/files/`, pinned to this checkout by its path, and `site-template/demo-content/` is its fictional content, copied in at the first `npm run dev` or `npm run build`.
- **Checks:** `npm test` runs the suite in about a minute, with no container. `npm run acceptance` takes the field's round trip through a real browser, in about half a minute, signs in, saves and publishes in three browser engines against a real Compose project, in about six minutes, and does the same with the live preview in another, in about three more, tries every way a page can leave the preview's pane in the three engines, in about a minute and a half, and needs Docker and Playwright's browsers. `npm run gate` does it all from a fresh clone: the suite on this machine and in Linux on the pinned Node, an audit of known vulnerabilities, a check for one copy of the Markdown reader, and the acceptance suite. `tests/lib/content.js` still shapes a site's content files in few lines for most tests of the Astro side, with the intake's own reading of settings; `tests/intake-*.test.js` hold the intake itself.
- **The Crepe field** (`src/cms/body/`): text elements, images, galleries and embeds in the editor, with the early check at opening and at Save, each later element a kept block. `/image` and `/gallery` choose from the image library or upload to it (ADR 0055), and `/embed` or a pasted address makes an embed (ADR 0024). Not there yet: post lists, forms, components, a table's caption and structured tables, a link's *Open in new tab* and internal links by search (ADR 0030's stages), and the site's body styles in the field, which need a build of their own.
- **Compose exists** (`compose/`): `docker compose up --wait` in a new site repository gives Forgejo with both factors and the proxy's list, the demo content as source files, and Sveltia from a generated configuration, in which a person signs in and saves, and a save reaches the public site.
- **Publishing** (`bin/konzilo-builder.js`, `src/build/`, `bin/konzilo-service.js`, `src/service/`, `src/cms/publishing/`): a save makes a commit, Forgejo's webhook or the service's look at each minute writes a build request, and the builder takes the source through the intake, commits and pushes the content repository, builds with Astro, writes the release's headers and redirects as rules for Caddy (`src/build/web-server.js`), moves `current` and records. The role check goes by who pushed, from Forgejo's feed. The service is only what publishing and the chooser's small pictures need so far, in the `editors` role. Each post's status shows in its form and on a *Publishing* page. Not there yet: the search index step, since Compose has no Typesense; the web server's `Link` headers and negotiation for Markdown alternates (issue #4), which are plain files so far. `konzilo-confirm` is an operator's command, with no page.
- **The intake:** one pure function, the body check in one file that imports nothing and is handed its reader, the ledger, the cross-file checks, the deletion guard, and the command, which exits 3 when the guard stops it. Not there yet: an Admin's changing or removing an automatic old address. A term has a page only on a site in one language, as the Astro side reads a term's file at its collection's root. The command hashes every original at every build, which a large site will want to skip, by the hash its LFS pointer already holds.
- **The live preview** (`bin/konzilo-preview.js`, `src/preview/`, `src/cms/preview/`, the `preview` service): the page beside the form, on an origin of its own, behind a gate that asks Forgejo, and a guard in each of its pages (`src/astro/preview-guard.js`) that keeps the page where it is and tells the pane where it would have gone. Not there yet: a cap on how many run on a shared server, with a static build past it, and stopping it at a deploy, which are the hosting layer's and step 12's; share links.
- **Not built yet:** the last of Sveltia's patches (a retry when two people save at once), the rest of the Node service behind `/_konzilo/`, share links, Compose on a real server. A site cannot yet declare components of its own: the registry is the rule data's. Forms render and the page's script sends them, but nothing answers at the endpoint.
- **The consent** (`src/consent/`, ADR 0049, 0050): its markup as pure functions, which the components wrap, the browser client, Matomo's own tracker beside the tag manager, a choice shared below a domain, counting without storage as a departure, and a consent script per language at `/_konzilo/consent/<language>.js` for pages Konzilo does not build. The folder imports nothing outside itself, so another site can copy it from a commit. Not there yet: an endpoint that takes records from those other pages, which therefore send none.
- **The lightbox** (`src/astro/lightbox.js`, `src/astro/modal.css`, ADR 0056): each image of a body opens in a dialog over the page, written by `Body.astro`, and a gallery steps through its images. It is the first use of the one dialog a page shows things over itself in. Not there yet: that dialog's other uses, a popup with content of its own, which wait for the component node.
- **Next:** by the spec's order, the remaining body elements. The design system comes in as a package when it has a first release (ADR 0054). The format and the integration are ready for a developer to build a site's templates on content files.
