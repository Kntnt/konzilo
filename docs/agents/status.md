State at 2026-11-13. Overwrite when it changes; this is not a history.

- **Repository:** public since 2026-11-12, `Kntnt/konzilo` (Thomas). The code is under `AGPL-3.0-or-later`, with a site's content and look left outside it by `SITE-EXCEPTION.md`, and whatever changes what the core does under it, and the name is under `TRADEMARKS.md` (Thomas, 2026-11-10, ADR 0057 and 0058). The rights are Kntnt Sweden AB's, and work by others goes into the core only under `CONTRIBUTOR-AGREEMENT.md`, by its author's line in `CONTRIBUTORS.md` (ADR 0059). What Konzilo is built on is named in `ACKNOWLEDGEMENTS.md` and, package by package, in `THIRD-PARTY.md`, which `node scripts/third-party.js` writes after a change to the lock. The editor's build writes the notices of what its bundle holds beside it, `third-party-notices.txt`, every package with its license text, those within Sveltia's own bundle too, from texts kept in `src/cms/notice-texts.json` where no installed package carries one, which `node scripts/notice-texts.js` writes after a raise the build refuses; the web image keeps and serves them (ADR 0072). `tests/licenses.test.js` holds the licenses of the lock and of those kept texts to one list, which holds Zlib and WTFPL too (Thomas, 2026-11-13, ADR 0059). Not settled, and his to settle: the registration of the name, which is not registered.
- **CI:** GitHub Actions stays off until the first usable version, when it goes on (Thomas, 2026-11-03). Until then `npm run gate` is the gate, as strict as CI would be: merge to `main` only after it passes on that commit. Do not settle for `npm test` in this checkout, which runs on this machine's Node rather than the pinned one.
- **Exists:** the npm package `@kntnt/konzilo`, one package at the repository's root: the content format (`content-format.md`, `src/format/`), the site description's checker (`src/site-description.js`), the settings groups, the post lists, with one ranking of related posts by score and freshness for a list ordered as related and for the recommended reading under an article, `relatedPosts()` (ADR 0070), the search index, the Astro integration (`src/astro/`), which builds a site from content files alone, the intake (`src/intake/`, `src/format/body.js`, `bin/konzilo-intake.js`), which writes them from source files, and the Crepe field for text elements (`src/cms/body/`). `bin/new-site` makes a site repository from `site-template/files/`, pinned to this checkout by its path, or, with `--release vX.Y.Z`, to that release's package, the file `kntnt-konzilo-X.Y.Z.tgz` each release carries, kept in the site's `vendor/`; it is run from a checkout at that tag, so that the site's files are the release's template, and so pins the release it was run from (ADR 0011). `site-template/demo-content/` is its fictional content, or the site repository's own `demo-content/` where it has one (ADR 0025), copied in at the first `npm run dev` or `npm run build`, and seeded as source files into Compose's Forgejo. The site template stays plain, with simple styles of its own, and a site takes a design package as `site-template/README.md` says (Thomas, 2026-11-13, ADR 0054).
- **Checks:** `npm test` runs the suite in about a minute, with no container. `npm run acceptance` takes the field's round trip through a real browser, in about half a minute, signs in, saves and publishes in three browser engines against a real Compose project, in about six minutes, and does the same with the live preview in another, in about three more, tries every way a page can leave the preview's pane in the three engines, in about a minute and a half, and takes the preview tab's toolbar and a site's nested components in the preview through the three engines, and needs Docker and Playwright's browsers. `npm run gate` does it all from a fresh clone: the suite on this machine and in Linux on the pinned Node, an audit of known vulnerabilities, a check for one copy of the Markdown reader, and the acceptance suite. `tests/lib/content.js` still shapes a site's content files in few lines for most tests of the Astro side, with the intake's own reading of settings; `tests/intake-*.test.js` hold the intake itself. Now and then a test's dev server never answers within its 90 seconds, and the same file passes at once when run again: #54 seeks why.
- **The Crepe field** (`src/cms/body/`): text elements, images, galleries and embeds in the editor, with the early check at opening and at Save, each later element a kept block. `/image` and `/gallery` choose from the image library or upload to it (ADR 0055), and `/embed` or a pasted address makes an embed (ADR 0024). Not there yet: post lists, forms, components, a table's caption and structured tables, a link's *Open in new tab* and internal links by search (ADR 0030's stages), and the site's body styles in the field, which need a build of their own.
- **Compose exists** (`compose/`): `docker compose up --wait` in a new site repository gives Forgejo with both factors and the proxy's list, the demo content as source files, and Sveltia from a generated configuration, in which a person signs in and saves, and a save reaches the public site. A local copy has one Admin, or the people `KONZILO_PEOPLE` lists, one in each role, each with a second factor (`src/people.js`). Each program finds its peers and its own folders by settings whose defaults are where Compose puts them (`src/arrangement.js`, ADR 0002), and the builder and the preview install a site's dependencies only when what they are installed from has changed (`src/site-code.js`).
- **Publishing** (`bin/konzilo-builder.js`, `src/build/`, `bin/konzilo-service.js`, `src/service/`, `src/cms/publishing/`): a save makes a commit, Forgejo's webhook or the service's look at each minute writes a build request, and the builder takes the source through the intake, commits and pushes the content repository, builds with Astro, writes the release's headers and redirects as rules for Caddy (`src/build/web-server.js`), moves `current` and records. The role check goes by who pushed, from Forgejo's feed. The service is only what publishing and the chooser's small pictures need so far, in the `editors` role. Each post's status shows in its form and on a *Publishing* page. A scheduled post goes live at its moment, and one whose moment had passed when the site first read it goes live at once, with a warning, while the editor stops a save with a moment in the past (ADR 0069). Each build makes the search index of what is published in Compose's own Typesense, and writes the web server's route to it, `/_konzilo/search`, with a key no page holds (ADR 0053); one that cannot be made leaves the release live, `unindexed` in the build's line. Not there yet: the web server's `Link` headers and negotiation for Markdown alternates (issue #4), which are plain files so far. `konzilo-confirm` is an operator's command, with no page.
- **A site's components** (ADR 0060): declared under `components` in its site description, or taken whole from a package's JSON by `componentsFrom`, with the site's own labels by `componentLabels`, read into the rule data by `siteRules()`, containers with their blocks and leaves with their label through the intake, the reader and the editor's early check, and what they hold checked by the `componentChecks` module, the site's own or a package's, in the intake. A component is given its body as a hast tree too, `content`, beside its slot, and in the live preview its block's mark, `data-konzilo-block`, to place on its own root, which the core does where it does not (ADR 0068). The site renders them, the hero, the section, the aside, the list and its five forms and the text roles through the design system's package (ADR 0068); the core gives their plain rendering. The design system takes these up in its own repository. Not there yet: a way for a component to have the core draw part of its tree (#55, for triage).
- **An article's parts** (ADR 0062): `breadcrumb`, `eyebrow`, `headline`, `subheadline`, `standfirst` and `teaser` as the core's fields, with what each falls back to in `src/format/article-parts.js`, which the head, the summary and search follow in an article and in a site's own type with a teaser; search, sharing and structured data as three groups in the source; `most` on a taxonomy field; and the breadcrumbs' own level by the type's setting. The built-in types `canvas`, `page` and `article`, with the taxonomies `authors`, `category` and `topics`, are in `src/format/built-in-types.js`, the read form's `builtIn` names them, and a template asks `builtInType(entry)`; the site template and its demo content are on them, a canvas without header and footer. Whether a post is an article is whether the structured data type it has is a kind of article (`structuredDataTypeOf()`, `isKindOfArticle()`), its own choice, else its type's in the settings, else its type's default, each among those its type offers, a site's own type's by `structuredDataTypes` in its site description; whether its type is the built-in article (`isArticle()`) says only which fields it has. A page and a canvas have a date, a last change and a teaser, and a canvas a name in breadcrumbs, and every built-in type's head follows its teaser, with the site's separator. A type's meta line is written by a format an Admin sets per type and language in the settings group `metaLine`, the article's alone with a default, and a template asks `metaLine(entry, Astro.url)` (`src/meta-line.js`). An article's authors keep the editor's order in its content file, its structured data names them so, each a `Person`, and a template's byline takes them from `authorsOf(entry)`. The site template's article shows the recommended reading under it, through `relatedPosts()`.
- **The editor's own fields** (ADR 0062 to 0065): the parts' fields with what they fall back to, the slug, the structured data type, the scheduled moment ahead; every image field from the library (`src/cms/image/`), Media in no menu; an article's authors as chips in the editor's order, suggested as a name is typed, and a new author added in a dialog (`src/cms/authors/`); the preview never enlarged, one choice of where it stands, a window of its own (`src/cms/preview-window/`), and blocks shown both ways by their paths; and the structure field (`src/cms/structure/`) for a type with `"editor": "structure"`. Each setting with a default is drawn by the core's `konzilo-setting` (`src/cms/settings/`), which shows the default where the file holds none and keeps a setting at its default out of the file (ADR 0033); a value written in a closed bar whose object the file lacks is kept by the closed bar's patch (ADR 0029). A post's form in field groups (ADR 0071), each one section with one menu over all its fields, the article's in their fixed order, the headline's optional parts buttons until wanted and the date and time, in UTC, under the status's choices, none with a label of its own, and a site's own fields on a built-in type in a group of their own, read from and written to a flat source file by a format of the editor's own (`src/cms/groups/`), the built-in types' files under `yaml-frontmatter` and a type of the site's own's, in its declared order, under `frontmatter`. A required field standing alone is a group of the core's by itself, whose menu never restores it to nothing. Not so: a required term, which only Sveltia's relation draws, keeps Sveltia's menu, which does, until a site needs required terms (Thomas, 2026-11-11). A label that describes, in the middle of one of Sveltia's phrases or of a refusal's reason, starts with a small letter, as in "Lägg till annan adress", but for an abbreviation, and one that names a field stands as the form shows it, "fältet Huvudrubrik" (ADR 0066).
- **The interface language** (ADR 0066): catalogues of the core's texts in `src/catalogues/`, British English the source and Swedish its translation, read through `src/catalogues.js`; the editor's own choice in Sveltia's preferences, else the site's `interfaceLanguage`, else its language's catalogue, else British English, with Sveltia's interface in it too, from a generated configuration per language. The form's labels, the settings groups' texts, a site's own labels, one text or one by language, and the texts of the body field, the preview and the publish status follow it. What visitors read of the core's own is in the same catalogues, under `site.`, and follows the content's language; `src/consent/` is handed them. Refusals and warnings carry their reason by name and values (`src/refusals.js`) and follow it too, those of `redirects.json` and `services.json` among them, each field named by its label, with British English on the command line and in the build log. No text of the core's that an editor or a visitor reads is outside the catalogues, the site template's frame, its recommended reading and its 404 page's text and a redirect page's among them, which a site may give its own of in `konzilo({ texts })`; what only a developer or an operator reads, the site description's checker and the command line and the build log, is British English in the code.
- **The intake:** one pure function, the body check in one file that imports nothing and is handed its reader, the ledger, the cross-file checks, the deletion guard, and the command, which exits 3 when the guard stops it. Not there yet: an Admin's changing or removing an automatic old address. A term has a page only on a site in one language, as the Astro side reads a term's file at its collection's root. The command hashes every original at every build, which a large site will want to skip, by the hash its LFS pointer already holds.
- **The live preview** (`bin/konzilo-preview.js`, `src/preview/`, `src/cms/preview/`, the `preview` service): the page beside the form, on an origin of its own, behind a gate that asks Forgejo, a guard in each of its pages (`src/astro/preview-guard.js`) that keeps the page where it is and tells the pane where it would have gone, and a script that draws a page again after a change under a view transition, at the scroll it had, with no empty frame between (`src/astro/preview-redraw.js`, ADR 0067). It opens in a tab of its own too, at its address, through Forgejo's sign-in by an OAuth client of its own, with the right asked again every ten minutes; it shows every saved post, whatever its status, and names a saved post the intake refuses where its page would be; and in a tab, a toolbar the gate puts into each page (`src/preview/toolbar.js`) gives the page's status and, for someone who may write, a link to its form (ADR 0032). Whoever may read the source sees it, a Reviewer, of the team `reviewers`, too, who can change nothing, the build refusing what a Reviewer pushes (ADR 0008). Not there yet: a cap on how many run on a shared server, with a static build past it, and stopping it at a deploy, which are the hosting layer's and step 12's; share links.
- **Forms** (`src/service/`, ADRs 0044, 0045): the service's role for visitors, a container on a network with no way out, takes `/_konzilo/forms/<form>` with its timing token, checks it by the form's declaration, and keeps each submission, with no address, in SQLite through `node:sqlite` in the `service-data` volume, with numbered schema steps; the role for editors gives Admins and Editors the *Submissions* page and a form's CSV, mails each submission to its form's recipients through SMTP once an Admin turns mail on (a local copy writes it to its log, `KONZILO_MAIL_TO_LOG`), and erases submissions past their form's retention; Admins set the mail server, each form's recipients and retention on the *Mail* page, kept in the service and never in Git, and find, export or erase a person's submissions on the *Personal data* page (ADRs 0003, 0044, 0045). Both roles mount the site's folder read-only and follow a replaced site description. Not there yet: Forgejo's own mail.
- **Not built yet:** the last of Sveltia's patches (a retry when two people save at once), the rest of the Node service behind `/_konzilo/`, share links, Compose on a real server.
- **The consent** (`src/consent/`, ADR 0049, 0050): its markup as pure functions, which the components wrap, the browser client, Matomo's own tracker beside the tag manager, a choice shared below a domain, counting without storage as a departure, by the server-log principle, with the right to object, and a consent script per language at `/_konzilo/consent/<language>.js` for pages Konzilo does not build, which may name the page's own policies. `docs/counting-visits-before-consent.md` is the site owner's guide to that departure. The folder imports nothing outside itself, so another site can copy it from a commit, with the catalogues, which its caller hands it for the core's own words. Not there yet: an endpoint that takes records from those other pages, which therefore send none.
- **The lightbox** (`src/astro/lightbox.js`, `src/astro/modal.css`, ADR 0056): each image of a body opens in a dialog over the page, written by `Body.astro`, and a gallery steps through its images. It is the first use of the one dialog a page shows things over itself in. Not there yet: that dialog's other uses, a popup with content of its own, which wait for the component node.
