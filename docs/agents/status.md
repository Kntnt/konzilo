State at 2026-11-03. Overwrite when it changes; this is not a history.

- **Repository:** private, `Kntnt/konzilo`. No license is chosen, and none is until Thomas says, with the public day.
- **CI:** GitHub Actions stays off until the first usable version, when it goes on (Thomas, 2026-11-03). Until then `npm run gate` is the gate, as strict as CI would be: merge to `main` only after it passes on that commit. Do not settle for `npm test` in this checkout, which runs on this machine's Node rather than the pinned one.
- **Exists:** the npm package `@kntnt/konzilo`, one package at the repository's root: the content format (`content-format.md`, `src/format/`), the site description's checker (`src/site-description.js`), the settings groups, the post lists, the search index, the Astro integration (`src/astro/`), which builds a site from content files alone, and the intake (`src/intake/`, `src/format/body.js`, `bin/konzilo-intake.js`), which writes them from source files. `bin/new-site` makes a site repository from `site-template/files/`, pinned to this checkout by its path, and `site-template/demo-content/` is its fictional content, copied in at the first `npm run dev` or `npm run build`.
- **Checks:** `npm test` runs the suite in about a minute, with no container. `npm run acceptance` signs in and saves in three browser engines against a real Compose project, in about two minutes, and needs Docker and Playwright's browsers. `npm run gate` does it all from a fresh clone: the suite on this machine and in Linux on the pinned Node, an audit of known vulnerabilities, a check for one copy of the Markdown reader, and the acceptance suite. `tests/lib/content.js` still shapes a site's content files in few lines for most tests of the Astro side, with the intake's own reading of settings; `tests/intake-*.test.js` hold the intake itself.
- **Compose exists** (`compose/`): `docker compose up --wait` in a new site repository gives Forgejo with both factors and the proxy's list, the demo content as source files, and Sveltia from a generated configuration, in which a person signs in and saves. A save only makes a commit: nothing runs the intake or rebuilds the site yet, the site's start build uses the published demo content, and the web server serves plain files, without the release's `_headers`, `_redirects` and `.md` alternates.
- **The intake:** one pure function, the body check in one file that imports nothing and is handed its reader, the ledger, the cross-file checks, the deletion guard, and the command, which exits 3 when the guard stops it. Not there yet: a preview's run of one post; an Admin's changing or removing an automatic old address; the command has no caller until saving through to a page is built, which also must hand it the list of Admins (`--admins`) and a whole clone, not a shallow one. The author address it reads from Git can be forged by anyone with write access, through Forgejo's API or a push, so before Compose holds real editors the check must read who pushed instead. A term has a page only on a site in one language, as the Astro side reads a term's file at its collection's root. The command hashes every original at every build, which a large site will want to skip, by the hash its LFS pointer already holds.
- **Not built yet:** the Crepe field and the rest of Sveltia's patches (a retry when two people save at once, the wording above a refusal), saving through to a published page, the Node service behind `/_konzilo/`, the live preview and share links, Compose on a real server. A site cannot yet declare components of its own: the registry is the rule data's. Forms render and the page's script sends them, but nothing answers at the endpoint.
- **Next:** by the spec's order, the Crepe field, which runs `src/format/body.js`, and then saving through to a published page in Compose. The design system comes in as a package when it has a first release (ADR 0054). The format and the integration are ready for a developer to build a site's templates on content files.
